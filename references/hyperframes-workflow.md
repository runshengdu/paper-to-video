# HyperFrames workflow

This skill renders with the HyperFrames CLI. The installed CLI in `--runtime-dir` is authoritative; run `hyperframes --help` there if a flag disagrees with this page.

## Runtime

The default runtime is `runtime/` under this skill, shared across papers. `scripts/bootstrap_runtime.py` installs pinned HyperFrames, GSAP, KaTeX, and their local vendor bundles there. Reuse that directory when it already has a working install. Do not install into a paper `output/` directory or into `references/`, `scripts/`, or `assets/`. Use another `--runtime-dir` only when the user names one.

Drive the CLI through that runtime:

```bash
python scripts/lint_scene_contract.py --animation-dir "<animation-dir>"
runtime/node_modules/.bin/hyperframes lint "<animation-dir>"
SNAPSHOT_TIMES="$(python scripts/review_times.py --timeline timeline.yaml)"
runtime/node_modules/.bin/hyperframes snapshot "<animation-dir>" --at "$SNAPSHOT_TIMES" --output "<review-dir>" --no-end --describe false
runtime/node_modules/.bin/hyperframes check "<animation-dir>" --at "$SNAPSHOT_TIMES"
runtime/node_modules/.bin/hyperframes render "<animation-dir>" --output "<mp4>" --fps 30 --quality high
```

Use `--quality draft` while iterating. Use `high` only after visual review. Apply the full YAML to `animation/` and render that directory.

## Production and publication

1. Check `runtime/` under this skill. Run `scripts/check_environment.py --required-font "<selected-font>" --burn-subtitles` when captions are enabled; omit `--burn-subtitles` only when they were explicitly declined. Pass `--runtime-dir` only when the user named a different runtime. If the check fails, report every missing component. Install only after the user explicitly asks for setup help, then rerun the check. Bootstrap with `scripts/bootstrap_runtime.py` (no extra flags) so packages land in `runtime/`.
2. Copy `assets/starter/` into `output/<paper_short_name>/animation/`. Run `scripts/apply_timeline.py` to generate `index.html`, `timeline.css`, and formula bindings. It copies KaTeX and GSAP from `runtime/vendor` when that directory exists; pass `--vendor-from` only for a non-default runtime.
3. Run `scripts/lint_scene_contract.py --animation-dir <animation-dir>`, then lint and run the mandatory snapshot review in `quality-control.md`. Do not render a pending video until that scene review passes.
4. Render a complete `--quality draft` MP4 to `review/<paper_short_name>.draft.mp4`, then run `scripts/review_encoded_video.py --timeline timeline.yaml --video review/<paper_short_name>.draft.mp4 --output-dir review/encoded-draft/`. Inspect its PNGs and JSON report. This is mandatory: composition snapshots are not proof that the encoded render respects clip visibility.
5. Only after both reviews pass, render to `review/<paper_short_name>.silent.mp4` (captions enabled) or `review/<paper_short_name>.pending.mp4` (captions declined). Never render directly over the final MP4.
6. When captions are enabled, run `scripts/generate_captions.py --timeline timeline.yaml --output captions.<language>.srt`, then run `scripts/burn_subtitles.py --timeline timeline.yaml --max-duration <seconds> review/<paper_short_name>.silent.mp4 captions.<language>.srt review/<paper_short_name>.captioned.pending.mp4`. Copy approved beat wording into YAML; caption generation keeps explicit newlines and does not wrap. Do not hand-edit the SRT to change line breaks. Inspect the captioned pending video's required review frames before publishing; fix and rerender if a subtitle overlaps content or is not legible.
7. Verify and atomically publish only after that review passes: `scripts/verify_output.py --subtitles burned --srt captions.<language>.srt --timeline timeline.yaml --max-duration <seconds> --replace-output output/<paper_short_name>/<paper_short_name>.mp4 review/<paper_short_name>.captioned.pending.mp4`. When captions were declined, verify and atomically publish with `scripts/verify_output.py --subtitles no --max-duration <seconds> --replace-output output/<paper_short_name>/<paper_short_name>.mp4 review/<paper_short_name>.pending.mp4`.

Do not call `preview` as a required gate; it is optional for the user. Agents inspect snapshot PNGs instead. Always pass `--describe false` to `snapshot`.

## Composition rules

- Root `index.html` is generated by `scripts/apply_timeline.py`. Do not hand-edit `data-start`, `data-duration`, `data-width`, `data-height`, or host `data-composition-src`.
- Nested scene files use a `<template>` wrapper. Their `data-composition-id` must equal the clip `id` and the `window.__timelines` key.
- Create one paused timeline per composition and register it synchronously. Never `.play()` for render-critical motion.
- Prefer `fromTo` inside nested scenes. Do not nest a child composition's timeline into the parent GSAP timeline.
- HyperFrames exclusively owns visibility of each nested scene root and `.clip` host. Never animate or set `opacity`, `autoAlpha`, `visibility`, or `display` on either element; animate a descendant instead.
- Load KaTeX from `animation/vendor/katex/` and GSAP from `animation/vendor/gsap/`. Do not fetch CDN assets during render.
- Formula scenes load `../formula_runtime.js` immediately after local KaTeX. That helper renders only within the scene root with `output: "html"`; scene scripts must not call `katex.render` or select `[data-tex]` globally. Reveal a formula in stages with extra formula nodes, not in-scene KaTeX.
- No `Date.now()`, `requestAnimationFrame`, unseeded randomness, or infinite `repeat: -1`.

## Time edits

Resolve the named clock time before editing. A single-clip interior time may be read from YAML. Use this command when clips overlap, the time is on a boundary, or the hit is ambiguous:

```bash
python scripts/resolve_time.py --timeline output/<paper>/timeline.yaml 1:23
```

Edit YAML and/or the hit scene file, then rerun `apply_timeline.py`.
